
**Objective:**
Generate full functional documentation in Confluence format for the target module or package I specify, based on the real behavior and purpose of the code.

**Instructions:**

1. **Read and analyze** all code contained in the target folder or package I specify.
2. Produce complete **functional documentation** describing what the system does, how it works, and why it works that way.
3. Use **clear English**, no emojis, and Confluence-compatible formatting.
4. Populate all existing Confluence pages I specify and **generate additional pages** where needed so the documentation is complete and consistent.
5. For every component, include:

   * Purpose
   * Inputs and outputs
   * Dependency graph
   * Process flow (Mermaid diagrams allowed)
   * Error handling
   * Logging and governance
   * Interaction with external services and internal dependencies
   * Configuration structure
   * Class and function responsibilities
6. Create a **top-level Confluence space structure** for the module, including:

   * Overview
   * Architecture
   * Data flow
   * Parameters and configuration
   * Modules and submodules
   * Operational integrations
   * Governance and traceability
   * Operational notes and edge cases
7. All content must be **professional**, **technical**, and suitable for internal engineering documentation.

**Deliverables:**

* A structured Confluence documentation set covering all module behavior.
* Complete descriptions of every relevant process from input ingestion through validation, business processing, integrations, outputs, and governance artifacts.
* Mermaid flow diagrams and UML where appropriate.
* Suggestions for missing documentation sections or pages.
