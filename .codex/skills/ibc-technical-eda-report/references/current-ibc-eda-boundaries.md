# Current IBC EDA Boundaries

Use for IBC report wording when no newer owner-approved evidence supersedes it.

- Work is pre-modeling. Do not declare ML table readiness.
- Customer is not universal grain. Some alerts are OLT/PON/uplink/infrastructure
  scope and intentionally do not carry affected end-customer population.
- `trap_events` is valuable as isolated intensity/lifecycle/count signal.
- `issues_on_subs` is current operational rail and appears composite, but lineage
  is still REVIEW until source owner confirmation.
- `issues_enrichment` is expected from Ale and must be profiled before use.
- Cisco data is excluded from initial scope to avoid vendor grammar drift.
- Exact duplicate identity is full-row fingerprint, not `id` alone.
- Direct topology/location joins remain HOLD unless coverage/no-fanout/as-of
  rules pass and owner approval is recorded.
